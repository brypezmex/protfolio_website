## Icons

### Pixelarticons

- **Used for:** every icon on the site - navigation, section headings, timeline
  node markers, skill group markers, project links, and contact fields.
- **Author:** Gerrit Halfmann
- **Source:** https://github.com/halfmage/pixelarticons
- **Licence:** MIT License - `Copyright (c) 2019 Gerrit Halfmann`
- **Licence text:** `frontend/src/components/ui/pixelarticons-LICENSE.txt`
- **Attribution required:** No. MIT only requires that the licence text and
  copyright notice be retained, which is why the full licence is vendored into
  the repository at the path above. The credit here is voluntary.

**How it is used.** The package is a **devDependency**, not a runtime one. Of
its 1,036 free icons the site uses 24, and `npm run build:icons` extracts just
those into `frontend/src/components/ui/pixelIcons.js` as inline SVG path data.
Nothing from the package ships in the browser bundle - only the extracted paths
do, which keeps the icon payload to a few hundred bytes and adds no runtime
dependency.

To change the icon set, edit the `ICONS` map in `frontend/scripts/build-icons.mjs`
and run:

```bash
npm run build:icons
```

### Streamline (not used - documented alternative)

The Streamline pixel icon set at
https://www.streamlinehq.com/icons/pixel was considered and not used. It is a
perfectly good set; the reasons for choosing Pixelarticons instead were:

1. **Licence obligations.** Streamline's free licence permits commercial use but
   **requires attribution with a visible hyperlink back to
   https://streamlinehq.com** on any project that uses the free assets.
   Pixelarticons is MIT and carries no such obligation, which is simpler for a
   personal site.
2. **Distribution.** Streamline assets are downloaded manually through an
   account rather than installed from a package registry, so they cannot be
   pinned, diffed, or regenerated by a script the way the current set can.

If you would rather use Streamline icons, this is what it takes:

- Download the SVGs and place them in `frontend/src/assets/icons/`.
- Either extend `scripts/build-icons.mjs` to read from that directory instead of
  `node_modules/pixelarticons/svg`, or paste the path data straight into
  `pixelIcons.js`. The `PixelIcon` component needs no changes as long as the
  artwork is on a 24-unit grid; if it is not, update `ICON_VIEWBOX`.
- **Add the required attribution.** A link reading "Free icons from Streamline"
  pointing at https://streamlinehq.com, somewhere visible - the site footer is
  the natural place. Without it the free licence is not satisfied.

### Self-hosting the fonts

The fonts currently load from Google Fonts, which means the site makes requests
to `fonts.googleapis.com` and `fonts.gstatic.com`. To remove that dependency -
worth doing if the site is served from a home server that should not rely on an
external CDN, or for privacy reasons:

```bash
npm install @fontsource/silkscreen @fontsource/pixelify-sans @fontsource/inter @fontsource/jetbrains-mono
```

Import them at the top of `frontend/src/main.jsx`, remove the `<link>` tags and
the two `preconnect` hints from `frontend/index.html`, and drop
`https://fonts.googleapis.com` and `https://fonts.gstatic.com` from the
Content-Security-Policy in `deploy/nginx.conf`.

## Everything else

No other third-party assets are used. Specifically:

- **No icon fonts, sprite sheets, or image assets.** The favicon, the Open Graph
  image, and the project preview schematics are all hand-authored SVG or CSS in
  this repository.
- **No UI or CSS framework.** All styling is written for this project.
- **No animation library.** Motion is `IntersectionObserver` plus CSS
  transitions.

Runtime dependencies are React and React DOM for the frontend, and Flask,
flask-cors, requests, Gunicorn, and python-dotenv for the optional backend.
